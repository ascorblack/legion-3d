# Публикация Legion 3D в магазинах

Публикует владелец с **корпоративного аккаунта**. Имя издателя настраивается в панели разработчика, не в коде. Агент не загружает расширение. Первую отправку в Chrome Web Store проводите вручную; API ниже — **только для обновлений существующей карточки**.

## Подготовка и первая отправка (Chrome)

1. Зарегистрируйте компанию в [Chrome Web Store Developer Dashboard](https://chrome.google.com/webstore/devconsole), пройдите проверку издателя, включите 2FA, оплатите регистрационный сбор, если панель его требует. Имя издателя задайте там.
2. Убедитесь, что `public/manifest.json` содержит актуальные версию и `homepage_url`; соберите `npm ci && node scripts/build.mjs --prod && node scripts/pack.mjs`. Проверяйте `unzip -l legion-3d-<version>-store.zip`: корень архива содержит manifest, bridge/game/background/notify JS, icons и (при наличии) sounds. Source maps и INSTALL-RU.txt в этом zip отсутствуют. GitHub архив `legion-3d-<version>.zip` дополнен INSTALL-RU.txt.
3. В панели нажмите **New item**, загрузите **store** zip вручную. Сохраните назначенный Extension ID. Заполните заголовок, короткое и полное описание из `store/listing-ru.md` / `store/listing-en.md`; выберите категорию Fun. Добавьте пять PNG из `store/screenshots/` (1280×800), промо 440×280 и marquee 1400×560 из `store/`. Проверьте на самой странице магазина, что нет чужих имён, cookies и личного чата.
4. Укажите сайт проекта `https://github.com/ascorblack/legion-3d` и **доступную публично** ссылку на `docs/PRIVACY.md` (перед Submit проверьте её из окна инкогнито; GitHub файл или GitHub Pages). Заполните вкладку **Privacy practices** честно: single purpose — 3D-режим игры; permissions — `storage` (хранит время последней проверки версии и найденный номер; без него фоновый скрипт теряет это при каждом засыпании); host match `https://play.multidonate.ru/c/*` — контент-скрипты работают только на страницах каналов; host permission `https://api.github.com/repos/ascorblack/legion-3d/releases/latest` — см. текст ниже; remote code — No. Использование данных — no data collected, sold or shared; только локальные настройки в localStorage; сам сайт обрабатывает игровые запросы. Подтвердите правила магазина и сохраните изменения.
5. Нажмите Submit for review вручную. После одобрения проверьте страницу карточки и расширение в чистом профиле. При необходимости в панели выберите **staged rollout** / поэтапную публикацию (если доступно): начните с небольшой доли, отслеживайте отзывы и ошибки, затем увеличивайте долю; автоматика ниже подаёт обновление на проверку и сама не выбирает процент раскатки.

### Текст обоснования host permission для GitHub API

> Доступ к одному адресу `https://api.github.com/repos/ascorblack/legion-3d/releases/latest` нужен фоновому скрипту, чтобы раз в 12 часов (и при запуске браузера) анонимным GET-запросом без cookies узнать номер последней версии расширения на GitHub и подсказать об обновлении тем, кто установил расширение из GitHub-архива. В установках из магазина `update_url` задан магазином, и расширение этот запрос не делает вовсе. Из ответа читаются только номер версии и ссылка на релиз; ничего не скачивается и не исполняется, данных о пользователе не отправляется. Permission `storage` хранит время последней проверки.

Пакет магазина содержит те же `background.js` и `notify.js`, что и GitHub-архив (проверку выполняет только установка без `update_url`). Если проверка Chrome сочтёт разрешение лишним для магазинной версии, удалите из store-манифеста `background`, `host_permissions`, `permissions` и `notify.js` — игра при этом работает без изменений (страница просто не получит ответа).

## OAuth для последующих Chrome-обновлений

1. В [Google Cloud Console](https://console.cloud.google.com/) создайте проект под владельцем, включите **Chrome Web Store API** в APIs & Services → Library. Настройте OAuth consent screen (External/Production или Internal для управляемого Workspace; при Testing refresh token может истечь через 7 дней). Создайте OAuth Client ID типа **Desktop app** в Credentials. Не сохраняйте client secret в репозитории.
2. Под учётной записью владельца магазина один раз получите authorization code через OAuth 2.0 authorization endpoint с scope `https://www.googleapis.com/auth/chromewebstore`, `access_type=offline`, `prompt=consent`, redirect URI `http://127.0.0.1:<port>` для локального приложения (URI должен быть разрешён для выбранного клиента). Обменяйте code на токены через `https://oauth2.googleapis.com/token` (`grant_type=authorization_code`, `client_id`, `client_secret`, `code`, `redirect_uri`). Сохраните **refresh_token** только в секретах GitHub Actions; не вставляйте его в issue, лог или чат. Для рабочего процесса можно использовать OAuth Playground с собственными OAuth credentials и тем же scope, соблюдая правила организации.
3. В GitHub репозитории Settings → Secrets and variables → Actions добавьте четыре repository secrets: `CWS_EXTENSION_ID` (ID из панели), `CWS_CLIENT_ID`, `CWS_CLIENT_SECRET`, `CWS_REFRESH_TOKEN`. Если хотя бы один отсутствует, Chrome шаг релиза пропускается без ошибки.
4. Для каждого обновления: увеличьте version в manifest, обновите CHANGELOG и проверяйте работу карточки; тег `v<manifest.version>` запускает тесты, production build, два zip и GitHub Release, затем PUT Chrome Web Store upload и POST publish (подача на проверку). API-успех означает отправку, **не** одобрение. Проверяйте review/status в dashboard; после одобрения магазин сам обновит установленное расширение. Если работает staged rollout, долей управляйте в панели. Не делайте тег до завершения первой ручной публикации и настройки секретов.

## Edge Add-ons (необязательно)

Создайте первую карточку вручную в [Microsoft Partner Center](https://partner.microsoft.com/dashboard/microsoftedge/overview), загрузите zip и заполните описание/конфиденциальность. После первой публикации выпустите API key и Client ID для [Edge Add-ons Update API v1.1](https://learn.microsoft.com/en-us/microsoft-edge/extensions/update/api/using-addons-api). Добавьте secrets `EDGE_PRODUCT_ID`, `EDGE_CLIENT_ID`, `EDGE_API_KEY`. Если любого нет, шаг пропускается. При теге CI загружает тот же store zip, ждёт успешной проверки пакета и подаёт draft на сертификацию; отслеживайте статус в панели. Ключ Edge не равен Google OAuth client secret. На ошибке/таймауте шаг завершится ошибкой и **не** подаст непроверенный пакет.

## Firefox: каталог Mozilla (AMO) — отдельное дополнение

Firefox-версий две, с разными ID:
- `legion-3d@ascorblack` — подписанный `.xpi` в релизах GitHub (канал unlisted, подпись за минуты, без каталога; об обновлениях сообщает уведомление в игре);
- `legion-3d-amo@ascorblack` — карточка в каталоге addons.mozilla.org (канал listed): собирается из store-архива (без проверки обновлений — AMO обновляет сам), отправляется на ручную проверку Mozilla вместе с архивом исходников (`git archive`), появляется в каталоге после одобрения.
Отдельный ID нужен потому, что AMO подписывает каждый номер версии один раз на дополнение.
Метаданные карточки — `store/amo-metadata.json` (категория, краткое и полное описание, ссылки, лицензия, заметки для ревьюера). Шаг релиза «Submit Firefox catalogue update (AMO listed)» использует те же секреты `AMO_JWT_ISSUER` / `AMO_JWT_SECRET`; его ошибка не ломает релиз на GitHub. Скриншоты карточки AMO добавляются вручную в кабинете.
